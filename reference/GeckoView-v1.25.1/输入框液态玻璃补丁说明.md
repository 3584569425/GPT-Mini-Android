# GPT Mini 输入框液态玻璃补丁说明

## 1. 补丁概述

GPT Mini 输入框的“液态玻璃”补丁，本质上是一个 **GeckoView 专用的 CSS 合成兼容补丁**。

该补丁没有重新绘制或替换 WebUI 的输入框，而是保留 WebUI 原有的液态玻璃 DOM 结构，针对 GeckoView 中容易出现的 `backdrop-filter` 失效问题进行修复。

当前实现采用两层注入：

1. Gecko WebExtension 页面脚本注入；
2. Android `MainActivity` 原生注入兜底。

双层注入的目的是避免扩展注入失败、注入过晚或页面局部刷新后样式失效。

---

## 2. 原始液态玻璃结构

WebUI 本身已经包含液态玻璃输入框结构，主要涉及以下元素：

- `.composer-shell`：输入框的外层定位容器；
- `.composer.codex-liquid-glass-original`：输入框主体；
- `.liquid-glass-warp`：负责背景模糊的玻璃层。

补丁不会替换这些结构，只对它们增加 GeckoView 兼容样式。

---

## 3. 问题根因

在 GeckoView 中，如果输入框的祖先元素 `.composer-shell` 长期包含以下属性：

- `transform`；
- `translate3d(...)`；
- `will-change`；
- 输入法升降过程中动态变化的 `transform`；

GeckoView 可能会将输入框提升为单独的 GPU 合成层。

输入框进入独立合成层后，其后代 `.liquid-glass-warp` 使用的 `backdrop-filter` 可能无法正确获取输入框后面的网页内容，从而导致背景模糊失效。

主要表现为：

- 输入框背景完全透明；
- 输入框后面的文字没有模糊；
- 只能看到输入框中的文字和按钮；
- 效果与普通浏览器中打开 WebUI 时明显不同。

---

## 4. 取消输入框外层的独立合成

补丁首先对 `.composer-shell` 进行处理：

```css
html.ai-mini-geckoview .composer-shell {
  transform: none !important;
  transition: none !important;
  will-change: auto !important;
}
```

### 作用说明

- `transform: none`：取消输入框外层的位移和独立合成；
- `transition: none`：避免输入法升降时遗留过渡动画；
- `will-change: auto`：取消强制 GPU 图层提升。

这样可以让 GeckoView 重新获取输入框后面的网页内容，并尝试恢复 `backdrop-filter` 的背景模糊能力。

---

## 5. 与输入法升降修复的关系

早期实现会通过修改 `.composer-shell` 的 `bottom` 或 `transform`，在输入法弹出时手动抬升输入框。

这种做法有两个问题：

1. Android 已经缩小了可视区域，再通过 CSS 抬升会造成输入框重复上移；
2. `transform` 会破坏 GeckoView 对 `backdrop-filter` 的合成，导致液态玻璃效果丢失。

当前实现改为：

- Android 使用 `SOFT_INPUT_ADJUST_RESIZE`；
- 输入法弹出时由系统缩小 GeckoView 可视区域；
- 输入框跟随视口自然上升和下降；
- 页面中的 `--keyboard-inset` 和 `--keyboard-shift` 保持为 `0px`；
- 清除旧版本写入 `.composer-shell` 的 `bottom`、`transform` 等样式。

因此，输入法升降和液态玻璃补丁实际上是相互关联的：只有不再使用额外的 `transform` 抬升输入框，GeckoView 的背景模糊才更容易正常工作。

---

## 6. 输入框主体样式补丁

补丁保留 WebUI 原来的 `.composer.codex-liquid-glass-original`，并补回 GeckoView 中容易丢失的半透明底色、边框和阴影：

```css
html.ai-mini-geckoview:not(.liquid-glass-off)
.composer.codex-liquid-glass-original {
  background: rgba(255,255,255,.06) !important;
  border: 1px solid rgba(255,255,255,.18) !important;
  border-radius: 29px !important;
  box-shadow:
    0 12px 42px rgba(0,0,0,.27),
    inset 0 1px 0 rgba(255,255,255,.10),
    inset 0 -1px 0 rgba(0,0,0,.08) !important;
  overflow: hidden !important;
  isolation: isolate !important;
}
```

### 各属性作用

#### 半透明底色

```css
background: rgba(255,255,255,.06);
```

给输入框增加非常淡的半透明玻璃底色。

当输入框后面是纯黑色或内容较少时，单独使用 `backdrop-filter` 不容易观察到效果。补充半透明底色后，可以避免输入框看起来完全透明。

#### 边缘高光

```css
border: 1px solid rgba(255,255,255,.18);
```

补回玻璃边缘的高光轮廓。

#### 圆角

```css
border-radius: 29px;
```

保持输入框的圆角胶囊形态。

#### 外部阴影

```css
0 12px 42px rgba(0,0,0,.27)
```

让输入框从网页背景上浮起，增强玻璃组件的层次感。

#### 内部高光与暗边

```css
inset 0 1px 0 rgba(255,255,255,.10),
inset 0 -1px 0 rgba(0,0,0,.08)
```

分别模拟玻璃顶部的高光和底部的暗边。

#### 裁剪玻璃层

```css
overflow: hidden;
```

确保内部模糊层不会超出输入框圆角。

#### 建立独立层叠上下文

```css
isolation: isolate;
```

降低输入框玻璃层与网页其他元素之间的层叠和混合干扰。

---

## 7. 背景模糊层补丁

真正负责模糊输入框后方内容的仍然是 WebUI 原有的 `.liquid-glass-warp`：

```css
html.ai-mini-geckoview:not(.liquid-glass-off)
.composer.codex-liquid-glass-original > .liquid-glass-warp {
  display: block !important;
  filter: none !important;
  position: absolute !important;
  inset: -1px !important;
  border-radius: inherit !important;
  background: transparent !important;
  backdrop-filter: blur(6px) saturate(140%) !important;
  -webkit-backdrop-filter: blur(6px) saturate(140%) !important;
  opacity: 1 !important;
  pointer-events: none !important;
}
```

### 各属性作用

#### 强制显示

```css
display: block;
opacity: 1;
```

避免玻璃层被 WebUI 的其他状态样式隐藏。

#### 覆盖输入框区域

```css
position: absolute;
inset: -1px;
```

让模糊层完整覆盖输入框，并额外向外扩展 `1px`，减少圆角边缘出现透明缝隙。

#### 继承圆角

```css
border-radius: inherit;
```

确保玻璃层和输入框主体的圆角保持一致。

#### 背景模糊和饱和度增强

```css
backdrop-filter: blur(6px) saturate(140%);
-webkit-backdrop-filter: blur(6px) saturate(140%);
```

- `blur(6px)`：模糊输入框后面的网页内容和文字；
- `saturate(140%)`：提高模糊背景的色彩饱和度，增强玻璃质感。

当输入框后方存在文字、代码块或卡片时，可以看到这些内容经过玻璃层后的模糊效果，而不是单纯叠加一个半透明背景。

#### 不阻挡输入操作

```css
pointer-events: none;
```

防止玻璃层拦截输入框、发送按钮和其他控件的点击或触摸事件。

## 8. 第一层：Gecko WebExtension 注入

相关文件：

```text
app/src/main/assets/extensions/ai-mini/page.js
```

关键函数：

```javascript
installGeckoLiquidGlassFallback()
```

该函数的工作流程为：

1. 检查当前 User-Agent 是否包含 `GPTMiniAndroidApp/`；
2. 确认页面运行在 GPT Mini App 的 GeckoView 环境中；
3. 给 `<html>` 添加 `ai-mini-geckoview` 类；
4. 动态创建 ID 为 `ai-mini-gecko-liquid-glass` 的 `<style>`；
5. 将 GeckoView 专用液态玻璃 CSS 插入页面。

使用 User-Agent 进行限制，可以避免补丁影响用户在普通桌面浏览器或手机浏览器中打开 WebUI 时的原始样式。

---

## 9. 第二层：MainActivity 原生兜底注入

相关文件：

```text
app/src/main/java/com/coimgrain/codexminiapp/MainActivity.java
```

主要涉及：

```java
injectMobileFixes()
androidWebViewCss()
```

页面加载完成后，原生代码会执行类似以下 JavaScript：

```java
document.documentElement.classList.add(
    "android-keyboard-mode",
    "ai-mini-geckoview"
);
```

然后将 `androidWebViewCss()` 返回的 CSS 动态插入页面。

这一层属于兜底机制，主要处理以下情况：

- WebExtension 启动较慢；
- WebExtension 没有及时完成注入；
- 页面内部发生局部刷新；
- WebUI 重新创建输入框；
- 页面加载流程导致扩展样式短暂失效。

---

## 10. 双层注入关系

两层注入的补丁内容基本相同：

| 注入层 | 位置 | 作用 |
| --- | --- | --- |
| WebExtension | `assets/extensions/ai-mini/page.js` | 页面脚本层的主要注入方式 |
| MainActivity | `MainActivity.java` | 页面加载完成后的原生兜底注入 |

双层注入不是为了叠加两套不同效果，而是为了确保至少有一层能够正常生效。

由于使用了相同或接近的 CSS 选择器和属性，重复注入通常不会让模糊程度翻倍，也不会重复创建输入框。

---

## 11. 补丁启用和关闭条件

补丁主要通过以下页面类名启用：

```css
html.ai-mini-geckoview
```

液态玻璃主体样式还包含以下限制：

```css
:not(.liquid-glass-off)
```

因此，当页面根元素带有 `liquid-glass-off` 类时，液态玻璃主体补丁不会强制启用，从而保留关闭液态玻璃效果的能力。

---

## 12. 当前方案的限制

当前实现可以恢复或模拟以下效果：

- 输入框背景内容模糊；
- 半透明玻璃底色；
- 玻璃边缘高光；
- 输入框内外阴影；
- 输入框后面有文字时的模糊效果；
- 输入法升降过程中尽量保持玻璃效果；
- 避免玻璃层阻挡输入和点击。

但该方案仍然属于 GeckoView 兼容补丁，并不等同于 Chromium 浏览器完整的 GPU 液态玻璃渲染。

如果 WebUI 原始效果还使用了以下技术：

- SVG displacement；
- 动态折射；
- Chromium 专属滤镜；
- 浏览器特定的 GPU 合成路径；
- GeckoView 尚未完整支持的 CSS 属性；

那么 App 内的效果可能无法与 Chromium 浏览器做到像素级一致。

因此，当前补丁的目标是：

> 保留 WebUI 原生液态玻璃结构，在 GeckoView 中恢复背景模糊、半透明、边缘高光和层次感，并尽量接近普通浏览器中的显示效果。

而不是完全重新实现一套液态玻璃渲染引擎。

---

## 13. 总结

整个输入框液态玻璃补丁可以概括为以下步骤：

1. 识别 GPT Mini App 内的 GeckoView 环境；
2. 给页面添加 `ai-mini-geckoview` 标记；
3. 取消 `.composer-shell` 的 `transform` 和 `will-change`；
4. 避免输入框被提升到破坏 `backdrop-filter` 的独立合成层；
5. 保留 WebUI 原有的输入框和玻璃层 DOM；
6. 恢复 `.liquid-glass-warp` 的背景模糊和饱和度增强；
7. 给输入框主体补充半透明底色、边框和内外阴影；
8. 使用 WebExtension 和 MainActivity 两层注入进行兜底；
9. 配合 Android `ADJUST_RESIZE` 实现输入法升降，避免再次使用 `transform` 破坏玻璃效果。
